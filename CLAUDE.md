# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cidx` (binary name **`cidx`**, alias **`repodex`**) — a Bun daemon that vectorizes codebases with local embeddings served by a pluggable backend — Ollama (`qwen3-embedding:0.6b` default; the bare tag is the 8B model) or a bare `llama-server` (`embedding.llamacppUrl`, OpenAI-compatible endpoints; `embedding.provider: auto|ollama|llamacpp`) — and exposes hybrid (semantic + BM25) code search over MCP. One long-lived daemon manages **multiple projects**; a thin CLI sends commands to it; AI agents connect over HTTP/stdio. `README.md` is the user-facing doc (English); the `docs/` folder holds the authoritative design, features, status, and changelog (`architecture.md`, `features.md`, `proposals.md`, `status.md`, `changelog.md`, `cpu-only-ops.md`, plus a `README.md` index); this `CLAUDE.md` is the AI-agent operating contract.

## Commands

```bash
bun install                  # install deps (frozen in CI)
bun run typecheck            # tsc --noEmit  — strict, must pass
bun test                     # all tests/*.test.ts
bun test tests/chunker.test.ts          # one file
bun test rrfMerge                       # by name/describe filter
bun run dev                  # daemon with --watch (src/index.ts)
bun run build:binary         # single binary → dist/cidx (grammars embedded)
bun run src/cli.ts start     # start daemon (≈ cidx start)
bun run src/cli.ts <cmd>     # ≈ cidx <cmd>  (index/list/search/find/refs/sync/.../doccheck)
```

Tests are pure-logic unit tests (`bun:test`) — they do **not** require a running embedding backend. They cover RRF, `buildWhere`, the AST chunker, tree-sitter grammars, registry (temp sqlite), job-queue + worker pool, bounded concurrency, config, and text helpers. Some load the LanceDB native module, so `bun install` must have run. `tests/integration/` adds a self-contained end-to-end battery: a **fake Ollama backend** on an ephemeral port + the **real daemon spawned as a subprocess** (mkdtemp `CIDX_HOME`, free ports) drive 19 ordered Control-API scenarios — it never touches the production daemon on 9371/9372 or the real `~/.cidx`, and never uses fixed ports.

Daemon data lives in `~/.cidx/` (`config.yml`, `db/` LanceDB tables, `meta.db` sqlite, `daemon.log`). Override the root with `CIDX_HOME`. A reachable embedding backend (Ollama, or `llama-server --embedding`) + a suitable model is required for real indexing/search (not for tests).

## Architecture — the big picture

**Three sub-programs, one binary.** `src/main.ts` is the `bun build --compile` target and dispatches by first arg: `__daemon` → `src/index.ts`, `__bridge` → `src/stdio-bridge.ts`, anything else → `src/cli.ts`. `src/runtime.ts` detects compiled-vs-dev (`IS_COMPILED` keys off `$bunfs` / `B:\~BUN` in argv) and produces the right spawn command for daemon/bridge. When editing CLI↔daemon handoff, both `runtime.ts` and the matching logic in `cli.ts`/`stdio-bridge.ts` must stay in sync.

**The daemon (`src/index.ts`).** Boots `Registry` (sqlite) → `JobQueue` (worker pool, size `jobConcurrency`) → `IndexManager` (the hub). It opens **two localhost-only HTTP servers before any indexing happens**, then `restore()`s watchers and re-enqueues half-finished projects. Servers:
- **MCP server** (`src/server/mcp.ts`, port 9371): `POST /mcp` Streamable HTTP (stateless), `GET /sse` legacy, `GET /health`. For AI agents.
- **Control API** (`src/server/control-api.ts`, port 9372): JSON endpoints the CLI calls (`/ping /indexes /index /search /search/batch /pack /find /references /outline /overview /dependencies /callgraph /impact /coupling /hotspots /deadcode /commits /apidiff /doccheck /doccheck/last /doctor /sync /reindex /stats /compact /querylog /events /bridge-session /shutdown`).
- **stdio bridge** (`cidx mcp`, `src/stdio-bridge.ts`): speaks MCP over stdin/stdout, forwards to the Control API, and **auto-starts the daemon if down**. Never logs to stdout (it's the JSON-RPC channel). It polls `GET /events` every 3 s and forwards job-completion `notifications/message` + `resources/list_changed` to the client, and registers a session via `POST /bridge-session` (an open session counts as daemon activity — the idle-shutdown guardrail).

**Hub: `IndexManager` (`src/core/index-manager.ts`).** Owns per-project `chokidar` watchers + a `.git/HEAD` branch watcher (auto-syncs on checkout). All mutations go through it: `createIndex`/`reindex`/`syncIndex` **enqueue an async job and return immediately** (unless the caller passes `wait` — `IndexManager.waitForIndexSettle` blocks up to `INDEX_WAIT_MS` for the final status, with `timedOut` past the budget; the MCP `index_project` tool and CLI `--wait` ride it) — search keeps serving while indexing runs. It also implements `searchIndex`/`searchAll`/`searchBatch` (multi-query fan-out over `searchIndex`/`searchAll`, results grouped per query with the envelope notes per group)/`findSymbol`/`findReferences` (honest `{refs, total, truncated}` envelope; `includeDocs` gates doc artifacts as evidence)/`repoOverview` and result enrichment (signature + `indexedAt` + ±N context lines read live from disk). **`searchIndex`/`searchAll` return a `SearchEnvelope` `{ results, blameNotARepo?, blameSkipped?, expanded?, expandNote? }`** (2.6.0 wire change — `/search`, MCP `structuredContent`, the stdio bridge and the CLI all carry it; it degrades to exactly `{results}` when nothing was requested; packs are deliberately blame-free and `findSymbol` stays a bare array). Every `searchIndex` call also writes one **`query_log`** row (expansion variants are never logged). **One-anchor project resolution:** every tool that takes a `project` also takes a `path` — the shared `resolveProjectScope(project?, path?, allWhenUnset)` anchors to the most-specific containing project (the `resolveProjectForFile` prefix match); nothing given → all projects (search family) or the single indexed project (report tools); `get_repo_overview`/`/overview` answer an anchorless multi-project call with a graceful non-error pick-one listing (`overviewPickOneNote`), so agents don't burn a round-trip on the ambiguity error. **Errors are self-healing:** every "unknown project" failure is built by the exported `indexNotFoundMessage` (available projects + likeliest intended name), and ambiguity errors say *"pass the 'project' (or 'path') argument"* — never CLI-flavored wording. New job types are added via `JobQueue.registerHandler(type, fn)` (see `core/types.ts`); registered today: `index`, `migrate` (O2 zero-downtime model/framing migration, shadow table + registry-txn swap), `doccheck` (D1c watch mode, enqueued after successful index/migrate jobs when `doccheck.watch` is on). The daemon publishes `job-completed`/`index-added`/`index-removed` events through `IndexManager.onIndexEvent` into a ring readable at `GET /events?since=<cursor>`.

**Persistence split:**
- `Registry` (`src/core/registry.ts`, **`bun:sqlite`**) — `indexes` (with a `table_name` column, an ephemeral `note` column written by the latest index job — currently the zero-file `CollectStats` explanation, cleared as soon as the table is non-empty again — and lazy migrations for legacy DBs — `tableNameFor(record)` is the single accessor), `file_cache` (mtime skip), `jobs` (survives restart; has a `priority INTEGER DEFAULT 0` column — claim order is priority DESC, FIFO within equal priority; `restore()` re-enqueues at `JOB_PRIORITY_BACKGROUND` -5), `embedding_cache` (content-hash → Float32 BLOB), `query_log` (bounded by `search.queryLogSize`, 0 = off), `doccheck_reports` (latest doc-check snapshot per project, D1c). Lazy column migrations follow the `PRAGMA` + `ALTER` + idempotent backfill pattern; new columns must not assume an existing DB has them. **Watcher counter reconciliation:** watcher writes bypass `setIndexStats`, so the watcher's `onFileSettled` callback (fired after every settled per-file event, success or failure) debounces a per-project `reconcileStats` (~1 s, one timer per project, `unref`'d) that recomputes file/chunk counts from `file_cache` + the LanceDB table and writes them through `setIndexCounts` — which deliberately leaves `lastIndexedAt` untouched, since the report caches (`docChunkCache`, `hotspotFeedCache`, call graph) key on it and a counter fix must not fake a data refresh. Reconcile skips while `isIndexing`; `removeIndex` and `shutdown` clear the timers.
- **LanceDB** (`src/services/db.ts`, `~/.cidx/db/`) — one table per project, `idx_<name>`. Fixed schema: every row carries `id, filePath, content, vector, language, symbolName, symbolType, startLine, endLine` + the nullable `doc` / `doc_vector` (2.4.0 docstring leg; see Search modes). **Legacy tables** (pre-2.4.0) lack those columns — `insertChunks` runs records through `stripUnknownColumns` (drops unknown fields, else LanceDB rejects the `add`) and every doc-leg query is gated on `tableColumns(table)`, so legacy tables run the exact legacy code paths until reindexed. **Public search results carry no embedding columns** — `IndexManager.stripEmbeddings` drops `vector`/`doc_vector` from `searchIndex`/`searchAll`/`findSymbol` returns (the pack and MCP `structuredContent` inherit the stripped rows); the in-daemon rerank/MMR machinery consumes them upstream, `doc`/`id_terms` stay.

**Indexing pipeline (`src/services/indexer.ts`):** `readProjectConfig` (`.cidx.json` — see below) → `buildIgnore` (.gitignore + .cidxignore + global + `.cidx.json` extra `ignore`) → `collectFiles` (optional git-tracked-only + `.cidx.json` `languages` allowlist via `extToLanguage` + the `maxFileSizeBytes` guard — files strictly larger than the limit are filtered before any work) → per-file `indexFile(target, filePath, registry?, signal?, embedModel?, framing?, maxFileSizeBytes?)`: mtime-skip → size-guard re-check (watcher path; `skippedOversized`, logged, never an error) → `chunkCode` → batched+bounded-concurrent embed via `embedTexts` (**texts are framed first** — `frameDoc` with the record's framing; the cache hashes the framed text) → `insertChunks` → finally `ensureVectorIndex` (ANN, above `vectorIndexThreshold` rows) + `ensureVectorIndex` on `doc_vector` + `ensureFtsIndex` (BM25 on `content` **and** `doc`, **plus the n-gram FTS over `symbolName`** for the `find_symbol` fuzzy tier — tables indexed before it existed never fuzzy-match; a doc-FTS failure warns, never fails the index). When `CONFIG.DOCSTRINGS` is on, chunks carrying a `doc` get a second `embedTexts` pass into `doc_vector` (`doc` is always written — null when absent; `doc_vector` only on embed success). Deleted-file cleanup runs against the cached set so files removed while the daemon was down are pruned (and it also prunes files newly filtered out by a `.cidx.json` `languages` allowlist or newly over `maxFileSizeBytes` — they're absent from `collectFiles` output).

**Per-project config (`src/core/project-config.ts`, `.cidx.json` at a project root):** `languages` (label allowlist, same labels as the `language` search filter; `extToLanguage` unifies `EXT_TO_GRAMMAR` + `TEXT_LANG_BY_EXT`), `ignore` (extra patterns into `buildIgnore`), `embedModel` (per-project embedding model), `framing` (per-project `none|auto` override of `embedding.framing`), `maxFileSizeBytes`, `doccheck` (`{ files, ignore }`). Read fresh on every index job **and every watcher event**; fields validated independently (invalid → dropped with warning; invalid JSON → skipped, never fails indexing). Identity-change semantics (model AND framing): pinned at `createIndex` (`embedModel`, `framing` on the record; `framing` null = unframed = byte-identical legacy), `syncIndex` escalates to a **zero-downtime `migrate` job** on change (shadow table + registry-txn swap — search keeps serving the old table throughout), and the watcher **skips writes** (removals still happen for filtered files) until the migration completes.

**Chunking (`src/chunking/`):** `chunker.ts` walks the AST and splits at function/class/method boundaries, descending into namespace/module/mod so nested symbols are extracted per-language. Chunks may carry a `doc` (2.4.0): `docstring.ts → extractDoc(top, inner, language)` — Python docstring (first body `string` statement, falling back to preceding comments), elsewhere the **contiguous run of comment-typed siblings directly before the symbol** (identity-checked by `node.id`; capped at `MAX_DOC_CHARS` 1200), attached **only to the first chunk** of a split symbol. Controlled by `CONFIG.DOCSTRINGS` at the indexer, not in the chunker. The chunk window is **token-aware**: `MAX = effectiveChunkChars(CONFIG.MAX_CHUNK_SIZE, CONFIG.MAX_CHUNK_TOKENS, CHARS_PER_TOKEN)` = `min(maxChunkSize, maxChunkTokens·4)` (`chunker.ts` exports `estimateTokens`/`effectiveChunkChars`; `CHARS_PER_TOKEN = 4`, no tokenizer bundled), and `STEP = MAX - OVERLAP_SIZE` — every consumer (`splitLarge`, `emitNode`, `emitClass`, `flushLoose`) reads these module consts, so changing `MAX_CHUNK_SIZE` or `MAX_CHUNK_TOKENS` propagates everywhere. **Cut edges are code-point-aligned** (2.6.1): `splitLarge` windows, the docstring `MAX_DOC_CHARS` cap and the signature cap all cut through `alignStartToCodePoint`/`alignEndToCodePoint` (`src/utils/text.ts`) — never slice content by raw UTF-16 index, or a chunk can end on half an astral character. **Char-limit-binding by default** (`maxChunkTokens` 512 · 4 = 2048 > default `maxChunkSize` 1500), so existing indexes are unchanged unless `maxChunkSize` is raised past 2048 or the cap is lowered; either change only affects new writes — existing projects must be **reindexed** to be re-chunked. `tree-sitter.ts` loads 16 embedded grammars (the `.wasm` files are imported with `with { type: "file" }` so `bun build --compile` embeds them — declared in `src/wasm.d.ts`); 15 come from `tree-sitter-wasms@0.1.13`, while **gdscript is vendored** at `src/chunking/wasm/` (built by `scripts/build-gdscript-wasm.sh`, ABI-guarded at LANGUAGE_VERSION 14 — see `docs/architecture.md`). Character-based fallback for `json`/`md`/`xml`/`rst`/unknown extensions (also Godot's `.gdshader`/`.tscn`/`.tres`/`.godot` text formats); the first four carry a `language` label via `TEXT_LANG_BY_EXT` (`chunker.ts`) so `language` filters work on doc corpora like `godot --doctool` class-reference dumps. **Lua is intentionally NOT bundled** (corrupts subsequent parses in the shared-WASM runtime) — it falls back to character chunking; any new grammar must pass the interleaved-determinism suite in `tests/tree-sitter.test.ts` before bundling.

**Search modes (`searchOnTable`):** `hybrid` = vector ∪ BM25/FTS merged with RRF (`src/utils/rrf.ts`, k=60); `vector` = semantic only; `text` = BM25 only (no embedding needed). **Docstring legs (2.4.0, on by default):** `searchTable` takes an explicit `column` (default `"vector"`), `searchTableText` a `columns` list (default `["content"]`) — when the table has the `doc`/`doc_vector` columns (`tableColumns`) and the caller didn't pass `doc:false`, `IndexManager.mergeWithExtraLegs` adds a doc-vector ANN leg and a doc-BM25 leg (plus, in hybrid mode, the `id_terms` identifier-part leg when the query splits into ≥2 words), then RRF-merges; results contributing via a doc leg carry `_docHit: true` → `[doc hit]` in CLI/MCP output. **Legacy behavior must be preserved byte-for-byte:** when no doc leg yields results, `combine` returns a single non-empty list sliced with its native metric (vector legs keep `_distance`, no `_score`) — don't "simplify" that into always-RRF. `CONFIG.DOCSTRINGS=false` (or a pre-2.4.0 table) removes the legs entirely. `find_symbol` is an exact/prefix `symbolName` scan (no vectors) with a **fuzzy tier** (n-gram FTS over `symbolName`, 2.6.0, default on, `fuzzy:false` opts out) that runs only when exact AND prefix both miss — hits carry `fuzzy: true`, and a symbol split into several chunks is returned **once**, as its head chunk (lowest `startLine` per `filePath`+`symbolName`, via `dedupeSymbolChunks`); `find_references` is a `content LIKE` candidate scan narrowed to whole-identifier matches in JS (`matchIdentifierLines`); `get_repo_overview` aggregates table metadata (no LLM, no reindex). **Reranker (on by default):** `searchIndex`/`searchAll` widen the fetch to `max(limit, RERANK_TOP_K, MMR_TOP_K)`, then `refineAndSlice` re-scores the top candidates via backend completion + yes/no-token logprobs (`src/services/rerank.ts`: Ollama `/api/generate` or llama.cpp `/v1/completions`; `search.rerank.url` may point the reranker at its own llama-server — an `--embedding` server cannot compute logits), re-sorts, and slices to `limit` — slotted *before* enrichment, with transparent fallback to RRF order; surviving results carry `_rerankScore`. `IndexManager.ensureRerankAvailable()` probes the resolved backend once (cached: Ollama `/api/show`, llama-server `/v1/models`) and auto-disables when the model is absent — default-on must not cause a per-search call storm. Per-call `rerank:false` / CLI `--rerank false` skips it. No reranker model is bundled (needs e.g. `qwen3-reranker-q8` in Ollama). **MMR diversification (on by default):** inside the same `refineAndSlice`, after reranking, `selectDiverse` re-orders the (already reranked) top candidates with Maximal Marginal Relevance (`src/utils/mmr.ts → selectMMR`; `MMR(d)=λ·rel(d)−(1−λ)·max_{d'∈selected} cos(d,d')`, default `search.mmr.lambda=0.5`; relevance min-max normalized to the [0,1] cosine scale so the tradeoff is scale-invariant) so the top results aren't near-duplicates of the same code. Pure-logic, no model; needs only the doc vectors, which are always present on LanceDB rows (`searchTable*` do not project columns away) — works in every mode. Per-call `mmr:false` / CLI `--mmr false` skips it; λ=0.5 chosen from live demos (0.7 left near-duplicates in the top slots, 0.3 over-diversified). **Query embedding is cached and framed:** the query vector comes from `cachedEmbed` (`src/services/embed.ts`) — the content-hash cache shared with indexing, keyed by `(model, sha256(embedded text))` — so a repeat search skips the backend embed round-trip (`text` mode needs no vector at all). **Framing applies to queries too:** `tableRows` (the single search-entry helper for base and expansion-variant queries alike) calls `frameQuery(query, rec.framing)` before the embed, so a framed project's queries and docs share a space — never embed a raw query against framed docs. **Path/surface boost (`search.boost`, on by default):** between the RRF merge and `refineAndSlice`, `applyPathBoost` (`src/utils/boost.ts`) re-scores **RRF-merged lists only** (a single-leg list carries its native metric under the same `_score` — re-scaling it would silently change its meaning; the manager gates on `rrfMerged`) with multiplicative path factors (shortPath 0.1 log-scale, sourceRoot 0.05 over `["src","lib","app"]`, testDemotion 0.85, generatedDemotion 0.8); `boost:false` / `--boost false` is byte-identical off. **Query expansion (`search.expand`, off by default — `model: ""`):** `expand:true` asks the configured instruct model for up to `maxVariants` (3) variant queries, runs each through the same per-project pipeline, and RRF-merges them into the base ranking; the envelope reports `expanded` (count) or an `expandNote` reason when it degraded — never silent; **variants are never query-logged**. **Blame enrichment (opt-in `blame:true`):** stamps `lastAuthor`/`lastCommitDate`/`churnCommits` per result via one `git blame --porcelain` per hit **file** (SHA-memoized per call, ≤ 8 files; extras → `blameSkipped`, non-repo → `blameNotARepo` in the envelope); applied before the `maxChars` budget. **`maxChars` budget:** after enrichment, `searchIndex`/`searchAll` apply a per-call `maxChars` via `applyCharBudget` (`src/utils/budget.ts`) — results are kept whole in ranked order while they fit (top-1 always returned, code never truncated), so a high `limit` can be used for recall without context bloat; it's server-side so it's consistent across HTTP/MCP/stdio/CLI. **`get_context_pack`:** one call over the same pipeline that also assembles, per hit, the file's symbol outline + forward imports + ±N context lines under a single pack-level char budget (`applyPackBudget`) — one round-trip instead of 4–6 search calls; the underlying search accepts the same `language`/`symbolType`/`pathGlob` filters as `search_codebase` (every layer copies them — the stdio bridge and control-api handlers are hand-maintained, easy to miss). **Report tools (`find_dead_code`, `search_commits`, `get_api_diff`, `get_change_impact`, `check_docs`, `get_dependencies`) return `structuredContent` alongside the rendered text** — the raw JSON report for programmatic consumers; new report tools should do the same. Enrichment signatures come from `deriveSignature` (`src/utils/text.ts`, called with the chunk's `language` at all four consumers): a `{` preceded by `:`/`,`/`(`/`=` opens an inline object **type**, not the body — the collector keeps gathering until the real body brace (Allman lone `{` still ends the head), so multi-line heads like `async checkDocs(opts: { … }): Promise<T>` render whole; leading doc comments, docstrings and decorators are skipped via the per-language `COMMENT_STYLES` table (languages without a style — e.g. markdown — keep the legacy first-line behavior).

**Code intelligence (`get_dependencies` / `find_dead_code` / `get_call_graph` / `get_change_impact` / `get_api_diff` / `get_coupling` / `get_hotspots`):** all are additive, **require no schema change and no reindex**, reuse the tree-sitter parse recipe + the `find_references` whole-identifier foundation, and are wired through all 8 layers (tool-defs → mcp → control-api → **stdio-bridge**, which does NOT auto-discover — easy-to-miss → cli → format → index-manager). `getDependencies(filePath, project?, opts?)` = "what does a file import" + "who imports it": forward = `extractImports` (`src/chunking/imports.ts`, top-level AST import nodes per language, **no `await` between `setLanguage` and `parse`**) → `resolveImports` (`src/core/resolve.ts`, **every resolved path validated against the index** — no phantom edges; relative/external/system classified, suffix fallback for unknown source roots); reverse = an **on-demand, mtime-keyed in-memory graph** (`IndexManager.depGraphCache`, rebuilt only when the indexed-file set or any mtime changes — so it reflects watcher edits on the next call), inverted to get imported-by, capped by `limit` (default 200). `project` is inferred by `IndexRecord.path` prefix (most-specific wins; throws on none/ambiguous). `findDeadCode(project, opts?)` flags **potential dead code**: indexed symbols (function/method/class/interface/enum/struct/trait/record) with zero whole-identifier references, scored conservatively (`src/core/deadcode.ts → scoreDeadCode`: start 80, demote for exported/polymorphic/dynamic-hook/constructor/owner-class-referenced/common-name, bump Python `_private`; "exported" recovered from chunk text per-language since the index has no visibility flag). Reference counting is one combined-regex pass over `tableSymbolsWithContent` (`db.ts`, like `tableMetadata` but keeps `content`, drops `vector`) via `countReferences`; the **definition rule** excludes only a symbol's exact declaration line (recursion in the body still counts — no false-dead on recursive fns), and names are scanned in `NAME_REGEX_CAP` groups so no symbol is silently dropped. Test files + entry points are pre-excluded. **Both surface truncation** (`scannedFiles`/`truncated` on deps; `scannedSymbols`/`scannedChunks`/`truncated` on dead-code) — no silent caps. `searchCommits(project, opts?)` is git-history / commit-message search ("when/why was feature X added", file history) — runs `git log` **live** in the project dir (`src/services/git.ts → searchGitLog`: `-z` NUL-safe, `-i` case-insensitive, `execFile` **no shell** so no injection, path filter relativized and passed as a literal argv after `--`; `isGitRepo` checked first → returns `notARepo` instead of throwing), parsed by the pure `src/core/commits.ts → parseCommitLog` (fields are `\x1f`-separated; a commit header is anchored on a 40-hex SHA + `\x1f`, so a changed-file name — which has no `\x1f` — can't be mistaken for a new commit, letting `--name-only` files be split out in one pass through multi-line bodies). **No embedding, no LanceDB, no schema change, no reindex.** Filters: message `query` (regex), `path` (file/dir/glob history), `author`, `since`/`until` (git date syntax), `limit` (default 50), `withFiles` (changed files per commit); surfaces `count`/`truncated`/`notARepo`. `get_call_graph` / `get_change_impact` turn the same whole-identifier adjacency into cycle-safe caller/callee trees and a ranked 'if I change X, what breaks?' report (per-project call-graph cache keyed on `lastIndexedAt`); `get_api_diff` diffs exported-symbol surfaces between two git refs, re-parsing the base ref from git with the identical tree-sitter recipe. `get_coupling` reduces the mtime-keyed dependency graph to per-file fanIn/fanOut/instability (`externalImports` counted separately) banded topFanIn/changeMagnets/unstableLeaves (`src/core/coupling.ts`, pure); `get_hotspots` joins **live git churn** (`src/core/hotspots.ts`, score = churn × size log-scaled — size = chunk + distinct-symbol counts, an honest proxy, never called complexity) with dead-code density + coupling as debt signals, test/entry files demoted into `review`, bands critical ≥ 50 / warm ≥ 25, `since` window default `"90 days ago"`, `notARepo` reported; its table-derived feeds ride a `lastIndexedAt`-keyed snapshot (`hotspotFeedCache`) — churn is fresh per call, size is not. Churn counts commits touching each file, and **merge commits are not counted** (`git log --name-only` emits no file list for them) — the same rule governs blame's `churnCommits`; document this, don't "fix" it into a different unit. `checkDocs(opts)` is the **doc–code conformance checker** (proposal D1, deterministic — no Ollama, no schema change, no reindex): the pure engine `src/core/doccheck.ts` (all state injected; byte-for-byte reproducible) classifies every backtick span in the project's markdown docs into 13 classes and resolves each against the symbol set, whole-identifier occurrences (with `file:line` evidence), a **constant-literal table** (`const X = "y"` — a doc can name a literal *value*), the file universe (indexed files ∪ **every walked file** via `src/services/docfiles.ts` — the index is an under-approximation: `.sh`/`.wasm`/LICENSE are never indexed — ∪ root names ∪ the docs themselves), package.json deps/devDeps/scripts, and per-file symbol membership. **Hard rule: only a total-resolution miss of a total-resolution class (identifier/path/dep/endpoint/cmd/env) at confidence ≥ 90 is a `drift` finding; everything uncertain → `needsReview` (<90).** The intent shield: historical files (`HISTORICAL_FILE_RE` — changelog/release-notes/**proposals/roadmap**), fenced examples and planned headings count spans but never produce findings; prose-example heuristics and a vocabulary gate (bare extensions, `.git/…`, URI paths, `owner/repo:tag`, `<placeholders>`, CI labels, `project.godot`-style convention files, systemd unit names (`.service`/`.timer`/… — external artifacts; `SYSTEMD_UNIT_RE`), `~`/`../` paths, `OLLAMA_*` absent from code) skip or demote; identical claims (same doc/line/class/token/verdict) collapse into one finding (contiguous IDs); `<!-- cidx-doccheck-ignore -->` suppresses its own line + the next. Reverse coverage lists exported symbols no doc mentions (`undocumented`, advisory, confidence 40, `noUndocumented` off-switch). The evidence snapshot is **one `tableSymbolsWithContent` pass per index version** (`docChunkCache` keyed on `lastIndexedAt`; doc artifacts dropped — a doc claim can't prove another doc claim); `checked.indexFreshness` surfaces snapshot age (~1–2 s lag). Drift window: `since <ref>` (`gitCommitTimeAt`, which queries `git show -s --format=%at <ref>^{commit}` — annotated tags MUST be dereferenced, or git prints the tag header and the ref silently fails to resolve) or `window: true` (docs' own last commit) post-filters findings, degradations become notes. `.cidx.json` `doccheck` `{ files, ignore }` tunes the doc set. **D1b semantic judge (off by default):** `doccheck.judgeModel` (`DOC_CHECK_JUDGE_MODEL`, `""` = fully deterministic path) injects a local instruct model that re-judges `needsReview` items and can only **resolve them out** — it never produces drift findings (the ≥ 90 hard rule is untouched); `runDocCheck` is async with the judge injected as `opts.judge` (`src/services/docjudge.ts`), `checked.judge` reports what ran, per-call `judge:false` skips. **D1c watch mode (off by default):** `doccheck.watch` enqueues a `doccheck` job after every successful index/migrate job (the constructor's `onIndexEvent` subscription; double-enqueue-guarded, flag read at event time), which re-runs the check and UPSERTs the latest report into `doccheck_reports`; `cidx doccheck --last` / `GET /doccheck/last` / `check_docs { last: true }` read the stored snapshot — always surfaced with its timestamp ("NOT a fresh check"). CLI exit 1 **only** on drift findings. `isTestFile`/`isEntryPointFile`/`DEAD_CANDIDATE_TYPES` live in shared `src/core/filekinds.ts` (dead-code + reverse coverage use the same recipe).

**Config (`src/config.ts`):** priority **defaults < YAML < env vars**. YAML lookup: `$CIDX_CONFIG` → `./cidx.yml`/`.cidx.yml` → `~/.cidx/config.yml` (auto-created from `DEFAULT_CONFIG_YAML` if absent — the template is load-bearing: an existing install pins whatever it says, so new keys must ship defaulted-off/on-as-designed). Everything downstream imports the flattened `CONFIG` constant. **Ollama `num_ctx` is always sent explicitly** (`OLLAMA_NUM_CTX` → `CONFIG.OLLAMA_NUM_CTX`, default 1024, on both embed calls in `src/services/ollama.ts`; `RERANK_NUM_CTX` → `CONFIG.RERANK_NUM_CTX`, default 1024, in `scoreOne`) — Ollama otherwise allocates a 4096 context for every loaded model, which is memory paid forever for inputs that are ≤512 tokens. llama.cpp has no per-request context: a llama-server is sized at launch (`--ctx-size ≥ ollama.numCtx`) and serves ONE model whose `-a` alias must equal `ollama.model`. If you raise `MAX_CHUNK_SIZE` past ~4000 chars, raise both keys with it. 2.6.0 key families: `search.boost` (`BOOST_*`), `search.expand` (`EXPAND_*`; `model: ""` = off), `search.queryLogSize` (`QUERY_LOG_SIZE`; 0 = off), `embedding.framing` (`EMBEDDING_FRAMING`; `none|auto`), `indexing.maxFileSizeBytes` (`MAX_FILE_SIZE_BYTES`; 0 = off), `doccheck.judgeModel`/`judgeUrl`/`watch` (`DOC_CHECK_*`; judge/watch default off), `daemon.idleTimeoutMinutes` (`DAEMON_IDLE_TIMEOUT_MINUTES`; 0 = off). Per-project overrides live in a **`.cidx.json`** at the project root (`src/core/project-config.ts`) — see the indexing pipeline above.

**MCP tool schemas** are a single source in `src/server/tool-defs.ts`, consumed by both `mcp.ts` and `stdio-bridge.ts` — keep them in sync.

## Critical invariants (read before touching these areas)

- **Model compatibility is per-record now.** A table's vectors come from one model, tracked by `embedModel` on the `IndexRecord` (pinned at `createIndex` from `.cidx.json` `embedModel` ?? `CONFIG.OLLAMA_MODEL`). `searchIndex`/`searchAll` **embed the query with the record's model** — they no longer throw on a global-model mismatch. Backend note: query embeds route through the resolved backend (`services/embed.ts`); when switching Ollama → llama.cpp, keep the served alias equal to the old model string to reuse caches/tables, else reindex. A model change (or a **framing** change — the `framing` pin follows the same rules) escalates `syncIndex` to a **zero-downtime `migrate` job** (shadow table re-embed → registry-txn pointer swap → old table dropped; doctor detects stale shadows, restore re-enqueues interrupted migrates), and the watcher skips writes on a changed identity, so two models/framings never share a table. Caveat: `searchAll` across projects with different models mixes distances from different embedding spaces. `text` mode is exempt (no vectors).
- **Framing is part of the record's identity.** `IndexRecord.framing` (null = unframed = byte-identical legacy) is resolved from `embedding.framing`/`.cidx.json` `framing` (`none|auto`, preset by model prefix) and pinned like `embedModel`; docs are framed at the indexer (`frameDoc`, cache keys hash the framed text) and queries at `tableRows` (`frameQuery`) — never frame one side without the other, and never hash the raw text when the framed text is what's embedded.
- **`insertChunks` deletes by `filePath`, not by `id`** (`db.ts`) — when a file shrinks and yields fewer chunks, this prevents stale high-index chunks (`file#7`, `file#8`…) lingering. Writes are serialized per-table via `tableWriteLocks` to avoid createTable races.
- **Never split astral characters, and never serialize a lone surrogate.** A chunk (or doc, or signature) ending on half a surrogate pair serializes to a `\ud83d` escape in the embed request body, and strict JSON parsers (llama.cpp's nlohmann — NOT Ollama's lenient Go one) reject the whole request → the file silently fails to index on every sync. All content cuts go through `alignStartToCodePoint`/`alignEndToCodePoint` (`src/utils/text.ts`); the backend wire clients (`llamacpp.ts`, `ollama.ts`, rerank/expand prompt bodies) additionally pass outbound text through `sanitizeLoneSurrogates` (lone halves → U+FFFD; clean text byte-identical, so the hash-what-you-embed cache keys never drift).
- **`indexDirectory` directory-access safety.** If `baseDir` is inaccessible/unmounted, it does **zero** deleted-file cleanup and fails the job — otherwise an empty file list would wipe the whole table (data loss).
- **`removeIndex` cancels the job and `await`s `waitForJob` before `dropTable`.** Without this, an in-flight `insertChunks` can recreate the table after the drop, leaving an orphan not in the registry. Cleanup goes through `removeIndexDeep` (table + indexes + file_cache + jobs + embedding_cache).
- **Watcher vs full-index race.** The watcher takes an `isBusy` callback (`IndexManager.isIndexing`) and defers per-file writes while a full index/sync is running, on top of the per-table write lock.
- **LIKE escaping.** `sqlLikeLit` escapes `\ % _` with `ESCAPE '\'` everywhere a user-supplied token hits a `LIKE` (`buildWhere`, `searchSymbol`, `searchContent`, registry's `removeIndexDeep`). Without it, `_` in snake_case names means "any char" → false positives (e.g. `get_user` matching `getXuser`).
- **`restore()` re-enqueues both `indexing` and `ready` projects** at startup as incremental syncs (mtime cache + deleted-file cleanup catches offline changes). Interrupted jobs are marked `failed` (`markInterruptedJobs`) since the in-memory queue is lost on restart.
- **Embedding cache BLOB decode copies the buffer first** (`Uint8Array.from`) before reading as Float32Array — avoids pooled-buffer offset issues.
- **Security defaults are load-bearing.** Both servers bind `127.0.0.1` only; CORS is restricted to localhost origins; Streamable HTTP enables DNS-rebinding protection with an explicit `allowedHosts` list. Don't loosen these without reason.
- **The search envelope is the public wire shape.** `searchIndex`/`searchAll` return `SearchEnvelope` `{ results, blameNotARepo?, blameSkipped?, expanded?, expandNote? }`; `searchBatch` carries the same notes **per query group**; the pack and `findSymbol` deliberately keep their old shapes. New search-adjacent features must decide which shape they ride and degrade to exactly `{results}` when inactive.
- **Job priority is ordering-only.** Claim order is priority DESC then FIFO; `restore()`'s boot re-enqueues run at `JOB_PRIORITY_BACKGROUND` (-5), user-initiated jobs at 0. There is no scheduler, no preemption, no starvation logic — keep it that way unless a real case appears.
- **Idle shutdown must never fight the bridge.** An open stdio-bridge session (`POST /bridge-session`) counts as daemon activity; `shouldIdleShutdown` (`src/core/idle.ts`) is a pure function fed activity timestamps, and the idle exit is code 0 + a log line so systemd distinguishes it from a crash.
- **A `/ping` timeout does not mean "daemon down".** The daemon is single-threaded and the report tools (`check_docs`, `find_dead_code`, `get_hotspots`, …) run multi-second synchronous CPU passes that block its event loop, so every request — `/ping` included — queues until the pass finishes. Client-side liveness must go through `src/daemon-probe.ts → probeDaemon` (shared by `cli.ts` and `stdio-bridge.ts`), which returns `up | busy | down`: **`busy` = the control port accepts TCP but ping stayed silent**, i.e. the process is alive. Treat `busy` as alive (queue the real request; never spawn another daemon), and only `down` (nothing listening) as "not running". `doctor`'s `daemonCheck` renders `busy` as a `warn`, not a `fail`. **Report scans must yield:** multi-second CPU passes over chunks (`scanDocTokens` in `doccheck.ts`, `countReferences` in `deadcode.ts`, `buildCallEdges` in `callgraph.ts`) own the event loop unless sliced. `src/utils/cooperative.ts` (`sliceClock`/`yieldIfExpired`, `setImmediate` between chunks) is the established pattern: keep the synchronous pure function as the unit-tested reference and add a `…Cooperative` twin used by `IndexManager`, with an equivalence test that forces a yield per chunk (`sliceMs: 0`). `busy` is the fallback for genuinely un-sliced blocks, not a license to block for seconds.

## Strictness notes

`tsconfig.json` is maximally strict (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `isolatedModules`). Practical consequences: optional fields need real `undefined` handling (not just omission), indexed access returns `T | undefined`, and `import type` is required for type-only imports. The MCP SDK transport's `connect()` is cast (`as unknown as Parameters<typeof server.connect>[0]`) to work around `exactOptionalPropertyTypes` friction with the SDK — preserve that cast pattern when touching server setup.

## Version string is duplicated

The version appears in **five** places that must be bumped together on release: `package.json`, `src/server/mcp.ts` (`Server` info), `src/server/control-api.ts` (`/ping`), `src/stdio-bridge.ts`, and `src/cli.ts` (`CLI_VERSION`). The `web-install.sh` / Release workflow only fires on a pushed `v*` git tag.

## Index freshness (when this tool searches its own repo)

The index lags edits by ~1–2s (write-finish + debounce + embedding + LanceDB write). Content you just wrote in this session is likely **not** in the index yet — to confirm a fresh edit, read the file directly rather than re-searching.
