# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`cidx` (binary name **`cidx`**, alias **`repodex`**) — a Bun daemon that vectorizes codebases with a local Ollama (`qwen3-embedding`) and exposes hybrid (semantic + BM25) code search over MCP. One long-lived daemon manages **multiple projects**; a thin CLI sends commands to it; AI agents connect over HTTP/stdio. `README.md` is the user-facing doc (English); the `docs/` folder holds the authoritative design, features, status, and changelog (`architecture.md`, `features.md`, `status.md`, `changelog.md`, `cpu-only-ops.md`); this `CLAUDE.md` is the AI-agent operating contract.

## Commands

```bash
bun install                  # install deps (frozen in CI)
bun run typecheck            # tsc --noEmit  — strict, must pass
bun test                     # all tests/*.test.ts
bun test tests/chunker.test.ts          # one file
bun test rrfMerge                       # by name/describe filter
bun run dev                  # daemon with --watch (src/index.ts)
bun run build:binary         # single binary → dist/cidx (grammars embedded)
bun run src/cli.ts start     # start daemon (≈ cidx start)
bun run src/cli.ts <cmd>     # ≈ cidx <cmd>  (index/list/search/find/refs/sync/...)
```

Tests are pure-logic unit tests (`bun:test`) — they do **not** require a running Ollama. They cover RRF, `buildWhere`, the AST chunker, tree-sitter grammars, registry (temp sqlite), job-queue + worker pool, bounded concurrency, config, and text helpers. Some load the LanceDB native module, so `bun install` must have run.

Daemon data lives in `~/.cidx/` (`config.yml`, `db/` LanceDB tables, `meta.db` sqlite, `daemon.log`). Override the root with `CIDX_HOME`. A running Ollama + `qwen3-embedding` model is required for real indexing/search (not for tests).

## Architecture — the big picture

**Three sub-programs, one binary.** `src/main.ts` is the `bun build --compile` target and dispatches by first arg: `__daemon` → `src/index.ts`, `__bridge` → `src/stdio-bridge.ts`, anything else → `src/cli.ts`. `src/runtime.ts` detects compiled-vs-dev (`IS_COMPILED` keys off `$bunfs` / `B:\~BUN` in argv) and produces the right spawn command for daemon/bridge. When editing CLI↔daemon handoff, both `runtime.ts` and the matching logic in `cli.ts`/`stdio-bridge.ts` must stay in sync.

**The daemon (`src/index.ts`).** Boots `Registry` (sqlite) → `JobQueue` (worker pool, size `jobConcurrency`) → `IndexManager` (the hub). It opens **two localhost-only HTTP servers before any indexing happens**, then `restore()`s watchers and re-enqueues half-finished projects. Servers:
- **MCP server** (`src/server/mcp.ts`, port 9371): `POST /mcp` Streamable HTTP (stateless), `GET /sse` legacy, `GET /health`. For AI agents.
- **Control API** (`src/server/control-api.ts`, port 9372): JSON endpoints the CLI calls (`/ping /indexes /index /search /search/batch /find /references /outline /overview /dependencies /callgraph /deadcode /commits /sync /reindex /shutdown`).
- **stdio bridge** (`cidx mcp`, `src/stdio-bridge.ts`): speaks MCP over stdin/stdout, forwards to the Control API, and **auto-starts the daemon if down**. Never logs to stdout (it's the JSON-RPC channel).

**Hub: `IndexManager` (`src/core/index-manager.ts`).** Owns per-project `chokidar` watchers + a `.git/HEAD` branch watcher (auto-syncs on checkout). All mutations go through it: `createIndex`/`reindex`/`syncIndex` **enqueue an async job and return immediately** — search keeps serving while indexing runs. It also implements `searchIndex`/`searchAll`/`searchBatch` (multi-query fan-out over `searchIndex`/`searchAll`, results grouped per query)/`findSymbol`/`findReferences`/`repoOverview` and result enrichment (signature + `indexedAt` + ±N context lines read live from disk). New job types are added via `JobQueue.registerHandler(type, fn)` (see `core/types.ts`); `index` is the only registered type today.

**Persistence split:**
- `Registry` (`src/core/registry.ts`, **`bun:sqlite`**) — `indexes`, `file_cache` (mtime skip), `jobs` (survives restart), `embedding_cache` (content-hash → Float32 BLOB).
- **LanceDB** (`src/services/db.ts`, `~/.cidx/db/`) — one table per project, `idx_<name>`. Fixed schema: every row carries `id, filePath, content, vector, language, symbolName, symbolType, startLine, endLine`.

**Indexing pipeline (`src/services/indexer.ts`):** `readProjectConfig` (`.cidx.json` — see below) → `buildIgnore` (.gitignore + .cidxignore + global + `.cidx.json` extra `ignore`) → `collectFiles` (optional git-tracked-only + `.cidx.json` `languages` allowlist via `extToLanguage`) → per-file `indexFile`: mtime-skip → `chunkCode` → batched+bounded-concurrent embed (cache read → Ollama for misses → cache write; model = per-project `embedModel` ?? `CONFIG.OLLAMA_MODEL`) → `insertChunks` → finally `ensureVectorIndex` (ANN, above `vectorIndexThreshold` rows) + `ensureFtsIndex` (BM25 on `content`). Deleted-file cleanup runs against the cached set so files removed while the daemon was down are pruned (and it also prunes files newly filtered out by a `.cidx.json` `languages` allowlist — they're absent from `collectFiles` output).

**Per-project config (`src/core/project-config.ts`, `.cidx.json` at a project root):** `languages` (label allowlist, same labels as the `language` search filter; `extToLanguage` unifies `EXT_TO_GRAMMAR` + `TEXT_LANG_BY_EXT`), `ignore` (extra patterns into `buildIgnore`), `embedModel` (per-project embedding model). Read fresh on every index job **and every watcher event**; fields validated independently (invalid → dropped with warning; invalid JSON → skipped, never fails indexing). Model-change semantics: pinned at `createIndex`, `syncIndex` escalates to full reindex on change, the watcher **skips writes** (removals still happen for filtered files) until reindexed.

**Chunking (`src/chunking/`):** `chunker.ts` walks the AST and splits at function/class/method boundaries, descending into namespace/module/mod so nested symbols are extracted per-language. The chunk window is **token-aware**: `MAX = effectiveChunkChars(CONFIG.MAX_CHUNK_SIZE, CONFIG.MAX_CHUNK_TOKENS, CHARS_PER_TOKEN)` = `min(maxChunkSize, maxChunkTokens·4)` (`chunker.ts` exports `estimateTokens`/`effectiveChunkChars`; `CHARS_PER_TOKEN = 4`, no tokenizer bundled), and `STEP = MAX - OVERLAP_SIZE` — every consumer (`splitLarge`, `emitNode`, `emitClass`, `flushLoose`) reads these module consts, so changing `MAX_CHUNK_SIZE` or `MAX_CHUNK_TOKENS` propagates everywhere. **Char-limit-binding by default** (`maxChunkTokens` 512 · 4 = 2048 > default `maxChunkSize` 1500), so existing indexes are unchanged unless `maxChunkSize` is raised past 2048 or the cap is lowered; either change only affects new writes — existing projects must be **reindexed** to be re-chunked. `tree-sitter.ts` loads 16 embedded grammars (the `.wasm` files are imported with `with { type: "file" }` so `bun build --compile` embeds them — declared in `src/wasm.d.ts`); 15 come from `tree-sitter-wasms@0.1.13`, while **gdscript is vendored** at `src/chunking/wasm/` (built by `scripts/build-gdscript-wasm.sh`, ABI-guarded at LANGUAGE_VERSION 14 — see `docs/architecture.md`). Character-based fallback for `json`/`md`/`xml`/`rst`/unknown extensions (also Godot's `.gdshader`/`.tscn`/`.tres`/`.godot` text formats); the first four carry a `language` label via `TEXT_LANG_BY_EXT` (`chunker.ts`) so `language` filters work on doc corpora like `godot --doctool` class-reference dumps. **Lua is intentionally NOT bundled** (corrupts subsequent parses in the shared-WASM runtime) — it falls back to character chunking; any new grammar must pass the interleaved-determinism suite in `tests/tree-sitter.test.ts` before bundling.

**Search modes (`searchOnTable`):** `hybrid` = vector ∪ BM25/FTS merged with RRF (`src/utils/rrf.ts`, k=60); `vector` = semantic only; `text` = BM25 only (no embedding needed). `find_symbol` is an exact/prefix `symbolName` scan (no vectors); `find_references` is a `content LIKE` candidate scan narrowed to whole-identifier matches in JS (`matchIdentifierLines`); `get_repo_overview` aggregates table metadata (no LLM, no reindex). **Reranker (on by default):** `searchIndex`/`searchAll` widen the fetch to `max(limit, RERANK_TOP_K, MMR_TOP_K)`, then `refineAndSlice` re-scores the top candidates via Ollama `/api/generate` yes/no-token logprobs (`src/services/rerank.ts`), re-sorts, and slices to `limit` — slotted *before* enrichment, with transparent fallback to RRF order; surviving results carry `_rerankScore`. `IndexManager.ensureRerankAvailable()` probes `/api/show` once (cached) and auto-disables when the model is absent — default-on must not cause a per-search call storm. Per-call `rerank:false` / CLI `--rerank false` skips it. No reranker model is bundled (needs e.g. `qwen3-reranker-q8` in Ollama). **MMR diversification (on by default):** inside the same `refineAndSlice`, after reranking, `selectDiverse` re-orders the (already reranked) top candidates with Maximal Marginal Relevance (`src/utils/mmr.ts → selectMMR`; `MMR(d)=λ·rel(d)−(1−λ)·max_{d'∈selected} cos(d,d')`, default `search.mmr.lambda=0.5`; relevance min-max normalized to the [0,1] cosine scale so the tradeoff is scale-invariant) so the top results aren't near-duplicates of the same code. Pure-logic, no model; needs only the doc vectors, which are always present on LanceDB rows (`searchTable*` do not project columns away) — works in every mode. Per-call `mmr:false` / CLI `--mmr false` skips it; λ=0.5 chosen from live demos (0.7 left near-duplicates in the top slots, 0.3 over-diversified). **Query embedding is cached:** the query vector comes from `cachedEmbed` (`src/services/ollama.ts`) — the content-hash cache shared with indexing, keyed by `(model, sha256(query))` — so a repeat search skips the Ollama embed round-trip (`text` mode needs no vector at all). **`maxChars` budget:** after enrichment, `searchIndex`/`searchAll` apply a per-call `maxChars` via `applyCharBudget` (`src/utils/budget.ts`) — results are kept whole in ranked order while they fit (top-1 always returned, code never truncated), so a high `limit` can be used for recall without context bloat; it's server-side so it's consistent across HTTP/MCP/stdio/CLI.

**Code intelligence (`get_dependencies` / `find_dead_code`):** both are additive, **require no schema change and no reindex**, reuse the tree-sitter parse recipe + the `find_references` whole-identifier foundation, and are wired through all 8 layers (tool-defs → mcp → control-api → **stdio-bridge**, which does NOT auto-discover — easy-to-miss → cli → format → index-manager). `getDependencies(filePath, project?, opts?)` = "what does a file import" + "who imports it": forward = `extractImports` (`src/chunking/imports.ts`, top-level AST import nodes per language, **no `await` between `setLanguage` and `parse`**) → `resolveImports` (`src/core/resolve.ts`, **every resolved path validated against the index** — no phantom edges; relative/external/system classified, suffix fallback for unknown source roots); reverse = an **on-demand, mtime-keyed in-memory graph** (`IndexManager.depGraphCache`, rebuilt only when the indexed-file set or any mtime changes — so it reflects watcher edits on the next call), inverted to get imported-by, capped by `limit` (default 200). `project` is inferred by `IndexRecord.path` prefix (most-specific wins; throws on none/ambiguous). `findDeadCode(project, opts?)` flags **potential dead code**: indexed symbols (function/method/class/interface/enum/struct/trait/record) with zero whole-identifier references, scored conservatively (`src/core/deadcode.ts → scoreDeadCode`: start 80, demote for exported/polymorphic/dynamic-hook/constructor/owner-class-referenced/common-name, bump Python `_private`; "exported" recovered from chunk text per-language since the index has no visibility flag). Reference counting is one combined-regex pass over `tableSymbolsWithContent` (`db.ts`, like `tableMetadata` but keeps `content`, drops `vector`) via `countReferences`; the **definition rule** excludes only a symbol's exact declaration line (recursion in the body still counts — no false-dead on recursive fns), and names are scanned in `NAME_REGEX_CAP` groups so no symbol is silently dropped. Test files + entry points are pre-excluded. **Both surface truncation** (`scannedFiles`/`truncated` on deps; `scannedSymbols`/`scannedChunks`/`truncated` on dead-code) — no silent caps. `searchCommits(project, opts?)` is git-history / commit-message search ("when/why was feature X added", file history) — runs `git log` **live** in the project dir (`src/services/git.ts → searchGitLog`: `-z` NUL-safe, `-i` case-insensitive, `execFile` **no shell** so no injection, path filter relativized and passed as a literal argv after `--`; `isGitRepo` checked first → returns `notARepo` instead of throwing), parsed by the pure `src/core/commits.ts → parseCommitLog` (fields are `\x1f`-separated; a commit header is anchored on a 40-hex SHA + `\x1f`, so a changed-file name — which has no `\x1f` — can't be mistaken for a new commit, letting `--name-only` files be split out in one pass through multi-line bodies). **No embedding, no LanceDB, no schema change, no reindex.** Filters: message `query` (regex), `path` (file/dir/glob history), `author`, `since`/`until` (git date syntax), `limit` (default 50), `withFiles` (changed files per commit); surfaces `count`/`truncated`/`notARepo`.

**Config (`src/config.ts`):** priority **defaults < YAML < env vars**. YAML lookup: `$CIDX_CONFIG` → `./cidx.yml`/`.cidx.yml` → `~/.cidx/config.yml` (auto-created from `DEFAULT_CONFIG_YAML` if absent). Everything downstream imports the flattened `CONFIG` constant. Per-project overrides live in a **`.cidx.json`** at the project root (`src/core/project-config.ts`) — see the indexing pipeline above.

**MCP tool schemas** are a single source in `src/server/tool-defs.ts`, consumed by both `mcp.ts` and `stdio-bridge.ts` — keep them in sync.

## Critical invariants (read before touching these areas)

- **Model compatibility is per-record now.** A table's vectors come from one model, tracked by `embedModel` on the `IndexRecord` (pinned at `createIndex` from `.cidx.json` `embedModel` ?? `CONFIG.OLLAMA_MODEL`). `searchIndex`/`searchAll` **embed the query with the record's model** — they no longer throw on a global-model mismatch. `syncIndex` escalates to a full reindex when a project's `.cidx.json` model changes, and the watcher skips writes on a changed model, so two models never share a table. Caveat: `searchAll` across projects with different models mixes distances from different embedding spaces. `text` mode is exempt (no vectors).
- **`insertChunks` deletes by `filePath`, not by `id`** (`db.ts`) — when a file shrinks and yields fewer chunks, this prevents stale high-index chunks (`file#7`, `file#8`…) lingering. Writes are serialized per-table via `tableWriteLocks` to avoid createTable races.
- **`indexDirectory` directory-access safety.** If `baseDir` is inaccessible/unmounted, it does **zero** deleted-file cleanup and fails the job — otherwise an empty file list would wipe the whole table (data loss).
- **`removeIndex` cancels the job and `await`s `waitForJob` before `dropTable`.** Without this, an in-flight `insertChunks` can recreate the table after the drop, leaving an orphan not in the registry. Cleanup goes through `removeIndexDeep` (table + indexes + file_cache + jobs + embedding_cache).
- **Watcher vs full-index race.** The watcher takes an `isBusy` callback (`IndexManager.isIndexing`) and defers per-file writes while a full index/sync is running, on top of the per-table write lock.
- **LIKE escaping.** `sqlLikeLit` escapes `\ % _` with `ESCAPE '\'` everywhere a user-supplied token hits a `LIKE` (`buildWhere`, `searchSymbol`, `searchContent`, registry's `removeIndexDeep`). Without it, `_` in snake_case names means "any char" → false positives (e.g. `get_user` matching `getXuser`).
- **`restore()` re-enqueues both `indexing` and `ready` projects** at startup as incremental syncs (mtime cache + deleted-file cleanup catches offline changes). Interrupted jobs are marked `failed` (`markInterruptedJobs`) since the in-memory queue is lost on restart.
- **Embedding cache BLOB decode copies the buffer first** (`Uint8Array.from`) before reading as Float32Array — avoids pooled-buffer offset issues.
- **Security defaults are load-bearing.** Both servers bind `127.0.0.1` only; CORS is restricted to localhost origins; Streamable HTTP enables DNS-rebinding protection with an explicit `allowedHosts` list. Don't loosen these without reason.

## Strictness notes

`tsconfig.json` is maximally strict (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `isolatedModules`). Practical consequences: optional fields need real `undefined` handling (not just omission), indexed access returns `T | undefined`, and `import type` is required for type-only imports. The MCP SDK transport's `connect()` is cast (`as unknown as Parameters<typeof server.connect>[0]`) to work around `exactOptionalPropertyTypes` friction with the SDK — preserve that cast pattern when touching server setup.

## Version string is duplicated

The version appears in **five** places that must be bumped together on release: `package.json`, `src/server/mcp.ts` (`Server` info), `src/server/control-api.ts` (`/ping`), `src/stdio-bridge.ts`, and `src/cli.ts` (`CLI_VERSION`). The `web-install.sh` / Release workflow only fires on a pushed `v*` git tag.

## Index freshness (when this tool searches its own repo)

The index lags edits by ~1–2s (write-finish + debounce + embedding + LanceDB write). Content you just wrote in this session is likely **not** in the index yet — to confirm a fresh edit, read the file directly rather than re-searching. See `search_codebase`'s tool description and `docs/status.md` (index freshness is marked done there).
